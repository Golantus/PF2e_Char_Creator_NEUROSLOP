# Лист героя: локальный конструктор PF2e

Версия 0.9.1, 12 октября 2026 г. React + TypeScript + Vite, Python + FastAPI, SQLite.

**Это рабочая сборка с реальной базой правил и расчетами. Полная автоматизация всех исключений PF2e еще не реализована.** Ограничения перечислены в `docs/coverage.md`; их нельзя считать автоматически проверенными только потому, что описание есть в каталоге.

## Запуск на Windows

1. Распакуйте весь архив в папку, например `C:\Games\pf2e-builder`. Не запускайте программу прямо из ZIP.
2. Установите Python 3.10 или новее, если его еще нет: https://www.python.org/downloads/windows/ . При установке отметьте **Add python.exe to PATH**.
3. Дважды нажмите **start.bat**. При первом запуске скрипт создаст отдельное окружение и установит зависимости. Для этого нужен интернет.
4. Браузер откроется автоматически. Если этого не произошло, откройте адрес из окна программы, обычно http://127.0.0.1:8765 .
5. Оставьте окно программы открытым, пока работаете. Для остановки нажмите Ctrl+C в этом окне.

Node.js и ручная сборка интерфейса для запуска не нужны: готовый frontend включен. Архив содержит проверенный снимок 992 страниц правил, поэтому повторно загружать сайт для начала работы не требуется. После установки зависимостей можно играть без интернета. При отсутствии базы программа запускает первоначальный импорт сама.

Запуск проверен в Linux на том же Python-приложении. Скрипты `.bat` подготовлены для Windows, но запуск на настоящей Windows в этой среде не проверялся.

## Как создать персонажа

1. Нажмите «Новый персонаж», введите имя и уровень, выберите класс, родословную, наследие и предысторию.
2. Откройте «Развитие» и выполните выборы каждого уровня. Можно сразу поставить 6-й или 20-й уровень: предыдущие решения остаются отдельными.
3. Распределите повышения характеристик, выберите специализацию и обученные навыки. Знания с разными специализациями учитываются отдельно.
4. В слотах способностей нажмите «Выбрать». Каталог ищет по русскому и английскому названию, показывает признаки, условия и полный текст.
5. Желтый индикатор требует проверки по источнику. Подтверждение сохраняется в истории. Красные требования автоматически запретят выбор.
6. Во вкладке «Способности» значок цепочки добавляет связанное правило, а «+» сохраняет текстовое решение по конкретной способности. Это также место для решений о компаньонах, фамильярах и других еще не автоматизированных вариантах.
7. Во вкладке «Заклинания» выберите источник, режим и уровень сотворения. Подготовка, репертуар, книга, фокусировка и врожденные заклинания разделены. Книга не расходует подготовленные слоты. Источники архетипов считаются отдельно.
8. В снаряжении добавьте предметы и отметьте экипированные. Бонус щита действует только при включенном «Щит поднят». Руны выбирайте по их конкретному виду и уровню.
9. Во вкладке «Полная сводка» скопируйте результат или сохраните TXT, Markdown либо JSON. Сводка содержит только полученные на текущем уровне способности с полными правилами. Общие статьи, списки невыбранных вариантов и отдельные будущие улучшения исключаются. Историю решений можно выгрузить режимом «Развитие по уровням». JSON можно импортировать как отдельного персонажа.

Персонажи автоматически сохраняются после изменений. Кнопка сохранения делает это сразу. История доступна по значку часов возле имени. При изменении уровня, класса или Free Archetype прежние выборы не удаляются: неподходящие становятся недействительными или неактивными.

Если обновить ранний выбор, проверьте список незавершенных решений и условий. Мастерство эксперта, мастера и легенды показывается с источниками. Условный либо нераспознанный числовой эффект можно добавить вручную во вкладке навыков или снаряжения; он выделен отдельно и действует только при включенном переключателе.

## Обновление правил и резервная копия

«База правил и настройки» показывает версии, счетчики, прогресс и ошибки. «Обновить базу правил» загружает новый снимок. Неудачная загрузка не заменяет рабочую версию. Импорт можно приостановить и продолжить, используя уже загруженные страницы. Закрытие программы также не удаляет скачанные части.

Готовую старую версию можно снова выбрать по умолчанию. Существующий персонаж остается на своей версии правил. Переход на текущую версию выполняется отдельной кнопкой, после него нужно проверить условия и историю выборов.

Все данные находятся в `data/builder.sqlite3`. Для резервной копии **закройте программу** и скопируйте папку `data`. JSON пригоден для переноса персонажа, но для точного восстановления его прежних правил нужна также соответствующая версия базы. Архив поставляется без тестовых персонажей.

## Для разработчика

- `backend/app/parser.py`, `parser_overrides.json`: секции Sphinx, полный HTML и текст, поля, таблицы, исключения.
- `backend/app/importer.py`: загрузка с повторными попытками, возобновление, контрольные суммы, переключение версий.
- `backend/app/migrations/001_initial.sql`, `db.py`: SQLite, версии, история персонажей.
- `backend/app/progression.py`, `choice_rules.py`: хронологическое применение решений и дополнительные слоты.
- `backend/app/prerequisites.py`: доступность на уровне выбора, зависимости, ручная проверка неоднозначностей.
- `backend/app/calculations.py`, `spells.py`: числовые расчеты, экипировка, источники заклинаний и усиление.
- `backend/app/exporter.py`, `main.py`: полные экспорты и локальный HTTP API.
- `frontend/src`: интерфейс; `frontend/dist`: готовая сборка.
- `backend/tests`: тесты на настоящих HTML-страницах, сохраненных в сжатом виде.
- `docs/import-report.json`, `docs/verification.md`: охват импорта и результаты проверок.

Для тестов откройте `test.bat`. Для изменения интерфейса установите Node.js 22+ и запустите `build-frontend.bat`. Скрипт `tools/package.py` создает ZIP с согласованной SQLite-копией и исключает окружение, зависимости и кэши.

На Linux: создайте virtualenv, установите `backend/requirements.txt`, затем выполните `python launcher.py`. Сервер слушает только localhost. Нет аккаунтов, облачной синхронизации, аналитики и внешних шрифтов.
